## Question: What is JavaScript?

## Answer:
JavaScript is a high-level, interpreted programming language that runs in the browser and on the server (via Node.js). It's the language of the web — every interactive website you use is powered by JavaScript. Unlike HTML and CSS which handle structure and styling, JavaScript handles behavior and logic.

In my projects, I use JavaScript for everything from form validation on the frontend to building REST APIs with Node.js on the backend. It's also used in mobile apps (React Native), desktop apps (Electron), and even machine learning (TensorFlow.js).

## Key Points:
- JavaScript is event-driven, single-threaded, and supports multiple paradigms (OOP, functional, procedural).
- It runs in the browser via engines like V8 (Chrome) and SpiderMonkey (Firefox).
- Node.js lets JavaScript run on the server side.
- It's dynamically typed — you don't declare variable types upfront.

## Interview Tip:
Mention that JavaScript is not the same as Java (a common beginner mistake). Highlight that it's the only language that runs natively in all browsers. Show awareness of its versatility beyond frontend.

---

## Question: What are the data types in JavaScript?

## Answer:
JavaScript has eight data types. There are seven primitive types: `String`, `Number`, `Boolean`, `Null`, `Undefined`, `Symbol`, and `BigInt`. Then there's one non-primitive type: `Object`.

Primitives are immutable — when you "change" a string, you're actually creating a new one. Objects are mutable — you can change their properties directly.

In real projects, I mostly work with strings, numbers, booleans, objects, and arrays (which are objects under the hood). I use `Symbol` for unique object keys and `BigInt` when I need to handle very large integers beyond `Number.MAX_SAFE_INTEGER`.

## Key Points:
- Primitive types: String, Number, Boolean, Null, Undefined, Symbol, BigInt.
- Non-primitive: Object (includes arrays, functions, dates, etc.).
- Primitives are stored by value; objects are stored by reference.
- `typeof null` returns `"object"` — this is a known JavaScript bug.

## Interview Tip:
Don't just list the types — explain the difference between primitives and objects. Mentioning the `typeof null` quirk shows depth. Knowing about `Symbol` and `BigInt` separates junior from mid-level.

## Question: What is the difference between primitive and reference data types?

## Answer:
Primitive types store their actual value directly. When you assign one primitive to another, JavaScript copies the value. Reference types store a reference (memory address) to the actual data. When you assign a reference type to another variable, both variables point to the same object.

This matters a lot in real code. If I copy an object like `const a = { name: "John" }; const b = a;`, changing `b.name` also changes `a.name` because both point to the same object in memory. This is a common source of bugs.

## Key Points:
- Primitives: stored on the stack, copied by value.
- Reference types: stored on the heap, copied by reference.
- Mutating a copied reference type affects the original.
- To avoid this, use spread operator (`{...obj}`) or `Object.assign()` for shallow copies.

## Interview Tip:
Give a quick code example showing the reference behavior. Mention that this is why immutability matters in React state management — you never mutate state directly.

## Question: What is the difference between `null` and `undefined`?

## Answer:
`undefined` means a variable has been declared but hasn't been assigned a value yet. JavaScript sets this automatically. `null` is an intentional assignment — it means "this value is empty."

I use `null` when I want to explicitly clear a value, like `let user = null` after logout. I don't manually assign `undefined` — that's JavaScript's default behavior.

## Key Points:
- `undefined`: variable declared but not assigned; function with no return value; missing object property.
- `null`: intentional absence of value; must be explicitly assigned.
- `typeof undefined` returns `"undefined"`, `typeof null` returns `"object"`.
- `null == undefined` is `true`, but `null === undefined` is `false`.

## Interview Tip:
Explain when you'd use each in practice. The `==` vs `===` comparison is a good follow-up point. Don't just say "they're different" — give context.

## Question: What is `NaN`?

## Answer:
`NaN` stands for "Not a Number." It's the result when a mathematical operation fails to produce a meaningful number. For example, dividing a string by a number, or calling `Number("hello")` gives `NaN`.

It's a special value — `typeof NaN` returns `"number"`, which is confusing but true. It's also the only value in JavaScript that's not equal to itself: `NaN !== NaN`.

In real projects, I check for `NaN` when parsing user input. If a user enters "abc" in a number field, `parseInt("abc")` returns `NaN`, and I need to handle that.

## Key Points:
- `NaN` is the result of failed numeric operations.
- `typeof NaN` is `"number"` (this is a quirk).
- `NaN !== NaN` — it's not equal to itself.
- Use `Number.isNaN()` to check for it (not `isNaN()` — see next question).

## Interview Tip:
Mention the quirk that `typeof NaN` is `"number"` — interviewers love this. Explain the difference between `Number.isNaN()` and the global `isNaN()`.

## Question: How do you check if a value is `NaN`?

## Answer:
The best way is `Number.isNaN(value)`. This is the modern, reliable method. It returns `true` only if the value is actually `NaN`.

The older global `isNaN()` is problematic because it tries to convert the value to a number first. So `isNaN("hello")` returns `true` because `Number("hello")` is `NaN`. That's usually not what you want.

## Key Points:
- `Number.isNaN(value)` — strict check, only returns `true` for actual `NaN`.
- `isNaN(value)` — coercive check, converts value to number first.
- `value !== value` — `NaN` is the only value that isn't equal to itself.
- `Object.is(value, NaN)` also works and handles other edge cases like `-0 === 0`.

## Interview Tip:
Always recommend `Number.isNaN()` over the global `isNaN()`. If you mention `Object.is()`, it shows deeper knowledge. Give a quick example of the coercion trap with global `isNaN()`.

## Question: What is the difference between `==` and `===`?

## Answer:
`==` is the loose equality operator. It compares values after converting them to the same type (type coercion). `===` is the strict equality operator — it compares both value and type without conversion.

I always use `===` in my projects. It avoids unexpected results like `0 == ""` being `true` or `null == undefined` being `true`. Using `===` makes behavior predictable.

## Key Points:
- `==` performs type coercion before comparing.
- `===` compares value and type without coercion.
- `"5" == 5` is `true`, but `"5" === 5` is `false`.
- Same applies to `!=` (loose) vs `!==` (strict).

## Interview Tip:
Give a few examples of surprising `==` behavior. State clearly that you use `===` by default — this is a best practice interviewers expect.

## Question: What is type coercion?

## Answer:
Type coercion is JavaScript automatically converting a value from one type to another. It happens with loose operators like `==`, `+`, `-`, and when using functions like `Boolean()`, `Number()`, or `String()`.

For example, `"5" + 3` gives `"53"` because JavaScript coerces the number `3` to a string. But `"5" - 3` gives `2` because the minus operator coerces the string to a number. This inconsistency is confusing and is why I prefer `===`.

## Key Points:
- Implicit coercion: happens automatically (e.g., `"5" + 3`).
- Explicit coercion: done intentionally (e.g., `Number("5")`).
- The `+` operator is special — if one operand is a string, it concatenates.
- Boolean coercion: `0`, `""`, `null`, `undefined`, `NaN`, and `false` are falsy.

## Interview Tip:
Mention specific examples like `"5" + 3` vs `"5" - 3`. Explain that understanding coercion helps debug unexpected behavior. Recommend using explicit conversion when needed.

## Question: What are truthy and falsy values?

## Answer:
In JavaScript, every value is either truthy or falsy when used in a boolean context (like an `if` statement). Falsy values are values that evaluate to `false`. Everything else is truthy.

The falsy values are: `false`, `0`, `-0`, `0n` (BigInt zero), `""` (empty string), `null`, `undefined`, and `NaN`. Everything else — including `""` (wait, empty string is falsy), objects, arrays, and non-empty strings — are truthy.

In real code, I use this for quick checks like `if (user)` instead of `if (user !== null && user !== undefined)`.

## Key Points:
- Falsy: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`.
- Truthy: everything else — objects, arrays, non-empty strings, non-zero numbers.
- Empty arrays `[]` are truthy, but empty objects `{}` are also truthy.
- `if (value)` is shorthand for `if (Boolean(value))`.

## Interview Tip:
Know the exact list of falsy values. A common mistake is thinking empty arrays or objects are falsy — they're not. Mention how truthy/falsy checks simplify conditional logic.

## Question: What are template literals?

## Answer:
Template literals are strings wrapped in backticks (`` ` ``) instead of quotes. They let you embed expressions using `${expression}` and create multi-line strings without `\n`.

I use them constantly — for string interpolation, multi-line messages, and building dynamic HTML. They're much cleaner than concatenating with `+`.

## Key Points:
- Use backticks (`` ` ``) instead of single or double quotes.
- Embed expressions with `${expression}`.
- Multi-line strings work without escape characters.
- Tagged templates allow custom processing of template literals.

## Interview Tip:
Show a before/after comparison: concatenation vs template literals. Mention tagged templates if you want to show advanced knowledge.

## Question: What are default parameters?

## Answer:
Default parameters let you set fallback values for function parameters when no value or `undefined` is passed. Before ES6, we had to do this manually inside the function body.

I use them for function options, API request configurations, and anywhere a parameter might be optional. They make functions cleaner and reduce the need for defensive checks.

## Key Points:
- Syntax: `function greet(name = "Guest") { ... }`.
- The default value is used when the argument is `undefined` or not provided.
- Default values can be expressions or function calls.
- Parameters with defaults come after required parameters.

## Interview Tip:
Mention that defaults are applied when the value is `undefined`, not when it's `null` or `0`. Show a real example like an API function with optional config.

## Question: What are rest parameters?

## Answer:
Rest parameters let a function accept an indefinite number of arguments as an array. They use the `...` syntax and must be the last parameter in the function signature.

I use them when building utility functions that need to handle variable arguments, like a logging function that accepts any number of messages, or a function that sums any number of numbers.

## Key Points:
- Syntax: `function sum(...numbers) { }`.
- Rest parameters are always an array.
- They replace the old `arguments` object (which is array-like but not an array).
- Must be the last parameter — no parameters after rest.

## Interview Tip:
Compare rest parameters with the `arguments` object. Explain that rest parameters give you a real array, which is better for methods like `.map()` and `.filter()`.

## Question: What is the spread operator?

## Answer:
The spread operator (`...`) expands an iterable (like an array or object) into individual elements. It's the opposite of rest parameters — rest collects, spread expands.

I use it constantly for copying arrays/objects, merging arrays, passing arguments to functions, and adding elements to arrays without mutating them. It's one of the most used ES6 features in my code.

## Key Points:
- Arrays: `const newArr = [...oldArr, 4]`.
- Objects: `const newObj = { ...oldObj, key: "value" }`.
- Function calls: `Math.max(...[1, 2, 3])`.
- Shallow copy only — nested objects are still referenced.

## Interview Tip:
Show practical examples like copying arrays and merging objects. Mention that spread creates shallow copies, which matters for nested data structures.

## Question: What are destructuring assignments?

## Answer:
Destructuring lets you extract values from arrays or properties from objects into distinct variables. It makes code much cleaner than accessing values one by one.

I use object destructuring for function parameters (especially React props), API responses, and config objects. Array destructuring is useful for swapping variables and getting values from functions that return multiple values.

## Key Points:
- Object: `const { name, age } = person;`.
- Array: `const [first, second] = [1, 2];`.
- You can rename variables: `const { name: userName } = user;`.
- You can set defaults: `const { role = "user" } = user;`.

## Interview Tip:
Show both object and array destructuring. Mention renaming and default values — these show practical knowledge. Give a React props example since it's very common.

## Question: What is optional chaining (`?.`)?

## Answer:
Optional chaining (`?.`) lets you safely access deeply nested properties without checking if each level exists. If any part of the chain is `null` or `undefined`, it short-circuits and returns `undefined` instead of throwing an error.

Before optional chaining, I had to write `if (user && user.address && user.address.city)` — now it's just `user?.address?.city`. It's one of the most practical ES2020 features.

## Key Points:
- `obj?.prop` — checks if `obj` exists before accessing `prop`.
- `obj?.[key]` — optional chaining with bracket notation.
- `obj?.method()` — checks if method exists before calling it.
- Returns `undefined` if any part of the chain is `null` or `undefined`.

## Interview Tip:
Give a real example like accessing API response data that might be missing. Compare the old way vs optional chaining to show the improvement.

## Question: What is nullish coalescing (`??`)?

## Answer:
The nullish coalescing operator (`??`) returns the right-hand operand when the left-hand operand is `null` or `undefined`. It's similar to the `||` operator, but `||` treats falsy values like `0` and `""` as empty.

I use `??` when I want to provide a default but only for truly missing values. For example, `const port = config.port ?? 3000` — if `config.port` is `0`, `||` would give `3000`, but `??` correctly gives `0`.

## Key Points:
- `null ?? "default"` returns `"default"`.
- `0 ?? "default"` returns `0` (unlike `||` which returns `"default"`).
- `"" ?? "default"` returns `""`.
- Can be combined with optional chaining: `user?.name ?? "Anonymous"`.

## Interview Tip:
Explain the key difference from `||`. The `0` example is the best way to show why `??` exists. Mention it's ES2020.

## Question: What are symbols?

## Answer:
Symbols are unique, immutable primitives introduced in ES6. Every symbol is unique — even two symbols created with the same description are different. They're mainly used as unique property keys for objects.

I use symbols when I need to add properties to objects without risking naming conflicts, especially when working with third-party code or adding metadata to objects.

## Key Points:
- Created with `Symbol("description")`.
- Always unique — `Symbol("a") !== Symbol("a")`.
- Used as object keys for guaranteed unique properties.
- Not enumerable — won't show up in `for...in` loops or `Object.keys()`.

## Interview Tip:
Explain why uniqueness matters — it prevents property collisions. Mention Symbol.iterator as a practical use case for making objects iterable.

## Question: What is BigInt?

## Answer:
BigInt is a numeric type introduced in ES2020 that can represent integers larger than `Number.MAX_SAFE_INTEGER` (2^53 - 1). Regular numbers lose precision beyond that point.

I've used BigInt in projects dealing with large IDs from databases, financial calculations, and cryptographic operations where precision matters. You create a BigInt by adding `n` to the end of a number or calling `BigInt()`.

## Key Points:
- Created with `123n` or `BigInt(123)`.
- Can represent arbitrarily large integers.
- Cannot be mixed with regular numbers — you must convert.
- `typeof 123n` is `"bigint"`.

## Interview Tip:
Give an example where regular numbers fail (like `9007199254740992 + 1` gives the same result as `9007199254740992`). Mention that BigInt doesn't support decimals — use `Number` for that.

## Question: What is strict mode (`"use strict"`)?

## Answer:
Strict mode is a restricted variant of JavaScript that catches common coding mistakes and prevents unsafe actions. You enable it by adding `"use strict"` at the top of a script or function.

In strict mode, using undeclared variables throws an error instead of creating global variables, duplicate parameters are disallowed, and `this` in functions defaults to `undefined` instead of the global object. ES6 modules are automatically in strict mode.

## Key Points:
- Enabled with `"use strict"` directive.
- Catches silent errors (undeclared variables, duplicate params).
- Prevents `this` from defaulting to global object in functions.
- Makes eval safer by not leaking variables into surrounding scope.

## Interview Tip:
Mention that modern code (ES6 modules, classes) is automatically strict. Give examples of what strict mode catches — undeclared variables is the most common one.

## Question: What is the `typeof` operator?

## Answer:

## Question: What is scope?

## Answer:
Scope determines where variables are accessible in your code. Think of it as the "visibility" of a variable — where can you access it from? JavaScript has three types of scope: global, function, and block scope.

When I write code, I think about scope to keep variables as close to where they're used as possible. This prevents bugs and makes code easier to understand.

## Key Points:
- Global scope: accessible everywhere.
- Function scope: accessible only within the function.
- Block scope: accessible only within the `{}` block (for `let` and `const`).
- Scope determines variable lifetime and accessibility.

## Interview Tip:
Explain that scope is about visibility, not just where code runs. Mention that understanding scope is key to understanding closures.

---

## Question: What is global scope?

## Answer:
Global scope is the outermost scope in JavaScript. Variables declared outside any function or block are in the global scope and can be accessed from anywhere in the code.

I avoid global variables as much as possible — they cause naming conflicts, make code hard to test, and create hidden dependencies. In browser code, the global object is `window`, and global variables become properties of `window`.

## Key Points:
- Variables declared outside functions/blocks are global.
- Global variables are accessible everywhere.
- They pollute the global namespace.
- In browsers, globals are properties of `window`.

## Interview Tip:
Mention that global variables are a common source of bugs in larger applications. Explain how module systems (ES modules, CommonJS) help avoid globals.

## Question: What is function scope?

## Answer:
Function scope means variables declared inside a function are only accessible within that function. They're created when the function runs and destroyed when it returns.

This is how `var` works — it ignores blocks and is scoped to the nearest function. But `let` and `const` have block scope, which is more precise.

## Key Points:
- `var` is function-scoped.
- Variables inside a function can't be accessed outside.
- Each function call creates a new scope.
- `let` and `const` inside functions are still block-scoped.

## Interview Tip:
Explain the difference between function scope (`var`) and block scope (`let`/`const`). Give an example showing how `var` leaks out of blocks.

## Question: What is block scope?

## Answer:
Block scope means variables declared with `let` or `const` inside a `{}` block are only accessible within that block. This includes `if` statements, `for` loops, and any other curly braces.

Block scope is more precise than function scope. It means variables don't leak out of loops or conditionals, which prevents many common bugs.

## Key Points:
- `let` and `const` are block-scoped.
- Variables exist only within their `{}` block.
- Prevents variables from leaking out of loops and conditionals.
- `var` ignores block scope — it's function-scoped.

## Interview Tip:

## Question: What is lexical scope?

## Answer:
Lexical scope (also called static scope) means that a function's scope is determined by where it's written in the code, not where it's called. Inner functions have access to variables from their outer (enclosing) functions.

This is how closures work — a function remembers the scope where it was created. I use this pattern all the time for data privacy and creating function factories.

## Key Points:
- Scope is determined at write time, not runtime.
- Inner functions access outer function variables.
- This is the foundation of closures.
- JavaScript uses lexical scoping (not dynamic scoping).

## Interview Tip:

## Question: What is scope chaining?

## Answer:
Scope chaining is how JavaScript looks up variables. When a variable is used, JavaScript first checks the current scope. If it's not found, it goes to the parent scope, then the grandparent scope, all the way up to the global scope.

If the variable isn't found anywhere in the chain, it throws a `ReferenceError`. This is why nested functions can access outer variables — they walk up the scope chain.

## Key Points:
- Variable lookup starts from the innermost scope.
- Moves outward through parent scopes.
- Stops at global scope.
- Throws `ReferenceError` if not found anywhere.

## Interview Tip:

## Question: What is hoisting?

## Answer:
Hoisting is JavaScript's behavior of moving declarations to the top of their scope during the compilation phase. Variable and function declarations are moved up, but their assignments stay in place.

`var` declarations are hoisted and initialized to `undefined`. `let` and `const` are hoisted but not initialized — they're in the Temporal Dead Zone until the declaration line. Function declarations are fully hoisted, including the body.

## Key Points:
- Declarations are moved to the top of their scope.
- `var` is hoisted and initialized to `undefined`.
- `let`/`const` are hoisted but not initialized (TDZ).
- Function declarations are fully hoisted.
- Assignments are NOT hoisted.

## Interview Tip:
Show code examples where hoisting causes unexpected behavior. Explain that `let` and `const` prevent this with the TDZ.

---

## Question: What gets hoisted in JavaScript?

## Answer:
Variable declarations (`var`, `let`, `const`) and function declarations get hoisted. Function expressions and arrow functions assigned to variables are NOT fully hoisted — only the variable declaration part is.

`var` declarations are initialized to `undefined` during hoisting. `let` and `const` are hoisted but stay in the Temporal Dead Zone until the line where they're declared. Function declarations including their entire body are hoisted.

## Key Points:
- `var x;` → hoisted, `x` is `undefined`.
- `let x;` → hoisted, but `x` is uninitialized (TDZ).
- `function foo() {}` → fully hoisted with body.
- `const foo = () => {}` → only `foo` is hoisted, not the arrow function.

## Interview Tip:
Give examples of each type. The difference between function declarations and function expressions being hoisted is a common interview question.

---

## Question: Why are `let` and `const` hoisted but inaccessible?

## Answer:
`let` and `const` are hoisted so the engine knows they exist in the scope, but they're not initialized until the code reaches the declaration. This creates the Temporal Dead Zone — a period where the variable exists but can't be accessed.

This is intentional. It prevents bugs where you accidentally use a variable before it's declared. If `let` and `const` behaved like `var` (initialized to `undefined`), you'd get silent bugs instead of clear errors.

## Key Points:
- Hoisting ensures the engine knows about the variable.
- TDZ prevents access before declaration.
- Throws `ReferenceError` if accessed in TDZ.
- This is a design choice to catch bugs early.

## Interview Tip:
Explain that TDZ is a feature, not a bug. Compare with `var`'s `undefined` initialization to show why TDZ is better.

## Question: What is the Temporal Dead Zone (TDZ)?

## Answer:
The TDZ is the period between when a `let` or `const` variable is hoisted and when it's actually declared in the code. During this time, the variable exists but can't be read or written — accessing it throws a `ReferenceError`.

The TDZ starts at the beginning of the scope and ends at the line where the variable is declared. It's called "temporal" because it's based on execution order, not code position.

## Key Points:
- TDZ exists for `let` and `const`, not `var`.
- Accessing a variable in TDZ throws `ReferenceError`.
- Starts at scope beginning, ends at declaration.
- Prevents accidental use before initialization.

## Interview Tip:
Show a code example that triggers TDZ. Explain why this is better than `var`'s `undefined` initialization — it catches bugs at runtime with a clear error.

## Question: What is an execution context?

## Answer:
An execution context is the environment where JavaScript code is evaluated and executed. It contains the code's variable environment, lexical environment, and `this` binding. Think of it as a container that holds everything needed to run a piece of code.

There are three types: global execution context (created when the script starts), function execution context (created when a function is called), and eval execution context (created when code runs inside `eval()`).

## Key Points:
- Created for every piece of code that runs.
- Global context: created when script starts, one per program.
- Function context: created for each function call.
- Contains variable environment, lexical environment, and `this`.

## Interview Tip:
Mention the three types. Connect execution context to the call stack — each context is pushed onto the stack when created and popped when done.

## Question: What is the call stack?

## Answer:
The call stack is a data structure that keeps track of function calls. JavaScript is single-threaded, so it uses a call stack to manage execution — when a function is called, it's pushed onto the stack, and when it returns, it's popped off.

The call stack works in LIFO order — last in, first out. If the stack gets too deep (like infinite recursion), it throws a "Maximum call stack size exceeded" error.

## Key Points:
- LIFO data structure — last in, first out.
- Tracks function execution order.
- Each function call creates a new stack frame.
- Stack overflow occurs with too many nested calls.

## Interview Tip:
Draw a simple diagram showing functions being pushed and popped. Mention the stack overflow error and when it happens (infinite recursion).

## Question: How does JavaScript execute code?

## Answer:
JavaScript executes code in two phases: the creation phase and the execution phase. In the creation phase, it scans the code, hoists declarations, and sets up the execution context. In the execution phase, it runs the code line by line.

The engine parses the code into an AST (Abstract Syntax Tree), compiles it to bytecode, and executes it. The JIT (Just-In-Time) compiler in V8 optimizes frequently executed code for better performance.

## Key Points:
- Creation phase: hoisting, memory allocation.
- Execution phase: running code line by line.
- V8 uses JIT compilation for performance.
- Single-threaded with an event loop for async operations.

## Interview Tip:
Mention the two phases and connect them to hoisting. If you know about V8's JIT compiler, mention it briefly.

## Question: What is memory creation phase?

## Answer:
The memory creation phase is the first phase of execution context creation. During this phase, JavaScript scans the code and allocates memory for all variables, functions, and parameters. Variables are set to their initial values (`undefined` for `var`, uninitialized for `let`/`const`).

This is when hoisting happens — declarations are registered and memory is reserved, even before the code actually runs.

## Key Points:
- First phase of execution context.
- Memory is allocated for variables and functions.
- `var` gets `undefined`, `let`/`const` are uninitialized.
- Function declarations are stored with their bodies.

## Interview Tip:
Connect this to hoisting — explain that this is when memory is allocated, which is why declarations are accessible before their line of code.

## Question: What is execution phase?

## Answer:
The execution phase is when JavaScript actually runs the code line by line. It assigns values to variables, executes function bodies, and evaluates expressions. This is when the code you wrote actually happens.

During execution, when a function is called, a new execution context is created and pushed onto the call stack. When the function returns, its context is popped off.

## Key Points:
- Second phase — code runs line by line.
- Variables get their actual values.
- Functions are called, creating new execution contexts.
- The call stack manages the execution order.

## Interview Tip:
Mention that the execution phase is when assignments happen — this explains why `var` is `undefined` before its line runs (it was set to `undefined` in the creation phase).

## Question: What happens when a function is called?

## Answer:
When a function is called, JavaScript creates a new execution context and pushes it onto the call stack. The context includes the function's local variables, parameters, and a reference to the outer scope (lexical environment).

The function runs within this context. When it returns, the context is popped off the call stack, and execution continues where it left off. Local variables are garbage collected after the function returns.

## Key Points:
- New execution context is created.
- Pushed onto the call stack.
- Local variables and parameters are initialized.
- Context is popped off when the function returns.
- Local variables are garbage collected.

## Interview Tip:
Connect this to the call stack and garbage collection. Mention that this is why recursive functions can cause stack overflow — each call adds a new context.

## Question: What is recursion?

## Answer:
Recursion is when a function calls itself to solve a problem by breaking it into smaller subproblems. Every recursive function needs a base case (to stop) and a recursive case (to continue).

I use recursion for tasks like traversing tree structures, solving mathematical problems (factorial, Fibonacci), and processing nested data. But I always make sure there's a proper base case to avoid infinite loops.

## Key Points:
- Function calls itself.
- Must have a base case to stop.
- Must have a recursive case to progress.
- Each call adds a frame to the call stack.

## Question: What is tail recursion?

## Answer:
Tail recursion is when the recursive call is the last operation in the function. This is important because some engines can optimize tail-recursive functions to avoid adding new stack frames — called tail call optimization (TCO).

Unfortunately, most JavaScript engines (including V8 in Chrome) don't fully support TCO. So tail recursion in JavaScript doesn't give you the stack overflow protection you'd get in languages like Scheme or Haskell.

## Key Points:
- Recursive call is the last operation.
- Enables tail call optimization (TCO) in some languages.
- V8 doesn't fully support TCO.
- Can be simulated with trampolining.

## Interview Tip:

## Question: What is a stack overflow?

A stack overflow happens when the call stack exceeds its maximum size. This typically occurs with infinite recursion or very deep function calls. JavaScript throws a "Maximum call stack size exceeded" error.

The stack size varies by engine — V8 typically allows around 15,000 frames. I watch out for this in recursive functions and make sure every recursion has a proper base case.

## Key Points:
- Caused by too many nested function calls.
- Common in infinite recursion.
- Throws "Maximum call stack size exceeded".
- Prevented by having proper base cases in recursion.

## Question: How does JavaScript manage memory?

## Answer:
JavaScript uses automatic memory management. When you create variables and objects, the engine allocates memory. When they're no longer needed, the garbage collector frees that memory.

The engine uses a mark-and-sweep algorithm — it marks objects that are still reachable (referenced) and sweeps away everything else. I help the garbage collector by cleaning up references when they're no longer needed.

## Key Points:
- Automatic memory management (garbage collection).
- Mark-and-sweep algorithm.
- Reachable objects are kept, unreachable are collected.
- Memory is allocated for variables, objects, and closures.

## Interview Tip:
Mention that you don't manually free memory in JavaScript. Explain that understanding garbage collection helps you avoid memory leaks.

## Question: What is garbage collection?

## Answer:
Garbage collection is the process where the JavaScript engine automatically frees memory that's no longer in use. It identifies objects that are unreachable (no references pointing to them) and deallocates their memory.

The most common algorithm is mark-and-sweep: the engine starts from root objects (global, current stack), marks everything reachable, and then collects everything that wasn't marked.

## Key Points:
- Automatic process — no manual memory management.
- Mark-and-sweep is the primary algorithm.
- Finds unreachable objects and frees their memory.
- Runs periodically, not continuously.

## Interview Tip:
Explain that garbage collection is not real-time — it runs when the engine decides it's needed. Mention that you can trigger it in some environments (like Chrome DevTools) for testing.

## Question: What is a memory leak?

A memory leak happens when your code keeps references to objects that are no longer needed, preventing the garbage collector from freeing that memory. Over time, the app uses more and more memory until it slows down or crashes.

Common causes include forgotten event listeners, detached DOM nodes, closures that capture large objects, and global variables that keep growing. I profile memory usage in Chrome DevTools to catch leaks early.

## Key Points:
- Unintentional retention of objects that should be garbage collected.
- Common causes: event listeners, detached DOM, closures, global variables.
- Symptoms: increasing memory usage, slow performance.
- Can be detected with Chrome DevTools Memory tab.

In React, I use `useEffect` cleanup functions to remove event listeners. In Node.js, I'm careful with closures in middleware and avoid keeping references to large objects in module-level variables.

## Question: What is the `this` keyword?

## Question: What is the prototype?

## Answer:
Every JavaScript object has a hidden `[[Prototype]]` property that links to another object called its prototype. When you access a property that doesn't exist on an object, JavaScript looks up the prototype chain until it finds it or reaches `null`.

This is how JavaScript implements inheritance. You can set an object's prototype with `Object.create()` or access it with `Object.getPrototypeOf()`.

## Key Points:
- Every object has an internal `[[Prototype]]` link.

## Question: What is the prototype chain?

## Answer:
The prototype chain is the sequence of objects JavaScript walks through when looking up a property. It starts from the object itself, goes to its prototype, then the prototype's prototype, and so on until it reaches `null`.

This is how inherited properties work. For example, an array can use `.map()` because it inherits from `Array.prototype`, which inherits from `Object.prototype`.

## Key Points:
- Property lookup follows a chain of prototypes.
- Starts from the object, moves up the chain.
- Ends at `null` (the end of the chain).
- Objects inherit properties from their prototypes.
- `Array.prototype` → `Object.prototype` → `null`.

## Question: How does inheritance work in JavaScript?

## Answer:

When you use `class Child extends Parent`, JavaScript sets up the prototype chain so that `Child` instances inherit from `Parent.prototype`. The `super()` call in the constructor initializes the parent part of the object.

## Key Points:
- Prototype-based inheritance (not class-based like Java).
- `extends` keyword sets up the prototype chain.
- `super()` calls the parent constructor.
- ES6 classes are syntactic sugar over prototypes.
- `instanceof` checks the prototype chain.

# Part 6: Asynchronous JavaScript (121–140)

---

## Question: What is synchronous programming?

## Answer:
Synchronous programming means code runs line by line, in order. Each line must finish before the next one starts. If a line takes a long time (like a network request), everything after it is blocked.

This is the default behavior of JavaScript — it's single-threaded and processes one thing at a time. For operations that take time, we need async programming.

## Key Points:
- Code runs line by line, in order.
- Each operation blocks the next.
- Simple and predictable.
- Problematic for long-running operations (I/O, network).

## Interview Tip:
Explain the problem with synchronous I/O — it blocks the entire thread. This sets up the need for async programming.

---

## Question: What is asynchronous programming?

## Answer:
Asynchronous programming lets you start an operation and continue running other code while it completes. The operation runs in the background and notifies your code when it's done via callbacks, promises, or async/await.

This is essential for web applications — you don't want the UI to freeze while waiting for an API response.

## Key Points:
- Operations run in the background.
- Code continues executing while waiting.
- Results are handled via callbacks, promises, or async/await.
- Prevents blocking the main thread.
- Essential for I/O operations.

## Interview Tip:
Give real examples like API calls and file reads. Explain that async is necessary because JavaScript is single-threaded.

---

## Question: What is the event loop?

## Answer:
The event loop is the mechanism that allows JavaScript to perform non-blocking operations despite being single-threaded. It continuously checks the call stack and task queues, moving completed callbacks to the stack for execution.

When an async operation (like `setTimeout` or a fetch) completes, its callback goes to a queue. The event loop picks it up when the stack is empty and pushes it onto the stack.

## Key Points:
- Monitors the call stack and task queues.
- Moves callbacks from queues to the stack when the stack is empty.
- Enables non-blocking async operations.
- Has separate queues for microtasks and macrotasks.
- Runs continuously until the program ends.

## Interview Tip:
Draw a simple diagram showing the call stack, queues, and event loop. Explain the order: call stack → microtask queue → macrotask queue.

## Question: What are Web APIs?

## Answer:
Web APIs are browser-provided functions that JavaScript can call for operations that the language itself doesn't handle — like DOM manipulation, network requests, timers, and storage.

When you call `fetch()`, `setTimeout()`, or `document.getElementById()`, you're using Web APIs. They run outside the JavaScript engine, in the browser's native code.

## Key Points:
- Browser-provided APIs, not part of JavaScript core.
- Handle DOM, network, timers, storage, etc.
- Run outside the JavaScript engine.
- Examples: `fetch()`, `setTimeout()`, `localStorage`, `DOM APIs`.

## Interview Tip:
Explain that Web APIs are not part of the JavaScript language itself. They're provided by the browser environment (or Node.js for server-side APIs).

## Question: What is the callback queue?

## Answer:
The callback queue (also called the task queue or macrotask queue) holds callbacks from async operations like `setTimeout`, `setInterval`, and I/O operations. The event loop moves these callbacks to the call stack when it's empty.

Callbacks in the callback queue are processed one at a time, after all microtasks are done.

## Key Points:
- Also called the task queue or macrotask queue.
- Holds callbacks from macrotasks.
- Processed after microtasks.
- One callback is processed per event loop iteration.
- `setTimeout` callbacks go here.

## Interview Tip:
Explain the difference between the callback queue (macrotasks) and the microtask queue. Give examples of what goes in each.

---

## Question: What is the microtask queue?

## Answer:
The microtask queue holds callbacks from microtasks like `Promise.then`, `MutationObserver`, and `queueMicrotask()`. Microtasks have higher priority than macrotasks — they're processed before the callback queue.

After each macrotask, the event loop processes all microtasks before moving to the next macrotask.

## Key Points:
- Higher priority than the callback queue.
- Processed completely before the next macrotask.
- `Promise.then`, `catch`, `finally` go here.
- `queueMicrotask()` adds to this queue.
- `MutationObserver` callbacks go here.

## Interview Tip:
Explain that microtasks always run before macrotasks. Give an example showing Promise resolving before setTimeout.

## Question: What is a Promise?

## Answer:
A Promise is an object representing the eventual completion or failure of an asynchronous operation. It can be in one of three states: pending, fulfilled, or rejected.

Promises let you chain async operations with `.then()` and handle errors with `.catch()`. They're much cleaner than nested callbacks.

## Key Points:
- Represents an async operation's result.
- Three states: pending, fulfilled, rejected.
- `.then()` for success, `.catch()` for errors.
- `.finally()` runs regardless of outcome.
- Can be chained for sequential async operations.

## Interview Tip:
Explain the three states clearly. Show a simple Promise example. Mention that Promises replaced callback patterns for async code.

---

## Question: What are the states of a Promise?

## Answer:
A Promise has three states: pending (initial state, operation in progress), fulfilled (operation completed successfully), and rejected (operation failed). Once fulfilled or rejected, the state doesn't change.

When you create a Promise with `new Promise((resolve, reject) => { ... })`, it starts pending. You call `resolve()` on success or `reject()` on failure.

## Key Points:
- Pending: initial state, operation in progress.
- Fulfilled: operation completed successfully.
- Rejected: operation failed.
- State transitions are permanent (pending → fulfilled OR pending → rejected).
- Result is set when the state changes.

## Interview Tip:
Mention that the state can't change back. Give examples of when each state is used.

---

## Question: What is promise chaining?

## Answer:
Promise chaining connects multiple `.then()` handlers to perform sequential async operations. Each `.then()` receives the result of the previous one and returns a new Promise.

I use chaining for sequential API calls where each depends on the previous result. But async/await makes this much cleaner.

## Key Points:
- Chain `.then()` calls for sequential operations.
- Each `.then()` returns a new Promise.
- `.catch()` at the end handles errors from any step.
- Can be hard to read with many chains.
- Async/await is often preferred.

## Interview Tip:
Show a chaining example. Mention that async/await is usually cleaner for sequential operations. Give a `.catch()` example for error handling.

## Question: What is `Promise.all()`?

## Answer:
`Promise.all()` takes an array of Promises and returns a new Promise that resolves when all input Promises resolve, or rejects if any one rejects. The resolved value is an array of results.

I use it for independent async operations that can run in parallel — like fetching multiple API endpoints simultaneously.

## Key Points:
- Resolves when ALL promises resolve.
- Rejects if ANY promise rejects.
- Returns an array of results in the same order.
- Useful for parallel operations.
- Fail-fast: rejects immediately if any promise rejects.

## Interview Tip:
Mention the fail-fast behavior. Compare with `Promise.allSettled()` which waits for all promises regardless of outcome.

## Question: What is `Promise.allSettled()`?

## Answer:
`Promise.allSettled()` waits for all promises to settle (either fulfill or reject) and returns an array of objects describing each result. It never rejects.

I use it when I need to know the outcome of all operations, even if some fail — like processing a batch where individual failures shouldn't stop the rest.

## Key Points:

## Question: What is `Promise.race()`?

## Answer:
`Promise.race()` takes an array of Promises and returns a new Promise that resolves or rejects with the first promise to settle. It's like a race — the fastest one wins.

I use it for timeout patterns (racing a fetch against a timer) and for getting the fastest response from multiple sources.

## Key Points:
- Settles with the FIRST promise to settle.

I use it when I have multiple sources for the same data and want the first successful response.

## Key Points:

Async/await is syntactic sugar over Promises that makes asynchronous code look synchronous. `async` marks a function as asynchronous and ensures it returns a Promise. `await` pauses execution until a Promise resolves.

I use async/await for all my async code — API calls, database queries, file operations. It's much more readable than promise chains.

## Question: How does async/await work internally?

## Answer:
Under the hood, async/await is syntactic sugar over Promises. An `async` function returns a Promise. When you `await` a Promise, the function pauses and the event loop continues running other code. When the Promise resolves, the function resumes.

The engine essentially transforms async/await into Promise chains with generators or state machines internally.

## Key Points:
- `async` functions return Promises.
- `await` pauses execution and yields control back to the event loop.
- Resumes when the awaited Promise resolves.
- Internally transformed to Promise chains or state machines.
- Non-blocking — other code runs while waiting.

## Question: Explain the JavaScript Event Loop.

## Answer:
The event loop is a mechanism that allows JavaScript to perform non-blocking operations. It continuously checks if the call stack is empty, then picks the next task from the microtask queue or macrotask queue.

The order is: execute all synchronous code → process all microtasks → process one macrotask → repeat.

## Key Points:
- Call stack: executes synchronous code.
- Microtask queue: Promises, `queueMicrotask()`.
- Macrotask queue: `setTimeout`, `setInterval`, I/O.
- Microtasks always run before macrotasks.
- One macrotask per event loop iteration.

It's also called the callback queue or event queue.

## Key Points:
- Also called callback queue or macrotask queue.
- Holds macrotask callbacks.
- Processed one per event loop iteration.

## Question: What is heap memory?

## Answer:
Heap memory is where JavaScript stores objects, arrays, functions, and closures. Unlike stack memory, heap memory is dynamically allocated and doesn't have a fixed size. Objects are allocated on the heap when they're created.

The garbage collector manages heap memory, freeing unused objects.

## Key Points:
- Stores objects, arrays, functions, closures.
- Dynamically allocated — no fixed size.
- Managed by the garbage collector.
- Objects are allocated when created.
- Larger and slower than stack memory.

## Question: What is stack memory?

## Answer:
Stack memory stores primitive values and function execution contexts. It's fast and automatically managed — values are pushed when created and popped when the function returns. The stack has a fixed size.

Primitives are stored directly on the stack, while objects are stored on the heap with a reference on the stack.

## Key Points:
- Stores primitives and execution contexts.
- Fast and automatically managed.
- Fixed size — stack overflow if exceeded.
- LIFO structure.
- Primitives are stored by value.

## Interview Tip:

## Question: How are primitive values stored?

## Answer:
Primitive values are stored directly on the stack. When you assign a primitive to another variable, the value is copied. Each variable has its own copy of the value.

This is why primitives are immutable — changing one variable doesn't affect another.

## Key Points:
- Stored directly on the stack.
- Copied by value when assigned.
- Each variable has its own copy.
- Immutable — changing one doesn't affect others.
- Fast access.

## Question: How are objects stored?

## Answer:
Objects are stored on the heap. The variable holds a reference (pointer) to the object, not the object itself. When you assign an object to another variable, the reference is copied — both variables point to the same object.

This is why objects are mutable — changing one variable affects all references.

## Key Points:
- Stored on the heap.
- Variables hold a reference (pointer).
- Copied by reference when assigned.
- Multiple variables can reference the same object.
- Mutable — changes affect all references.

## Question: Implement deep clone().

## Answer:
```javascript
function deepClone(obj, seen = new WeakMap()) {
  if (obj === null || typeof obj !== "object") return obj;
  if (seen.has(obj)) return seen.get(obj);
  
  const clone = Array.isArray(obj) ? [] : {};

  for (const key in obj) {
    if (obj.hasOwnProperty(key)) {
      clone[key] = deepClone(obj[key], seen);

  }
  return clone;
}
```

Creates a deep copy handling circular references.

## Question: Implement event emitter.

## Answer:
```javascript
class EventEmitter {
  constructor() {
    this.events = {};
  }
  
  on(event, callback) {
    if (!this.events[event]) this.events[event] = [];
    this.events[event].push(callback);
  }
  
  emit(event, ...args) {
    if (this.events[event]) {
      this.events[event].forEach(cb => cb(...args));
    }
  }
  
  off(event, callback) {
    if (this.events[event]) {
      this.events[event] = this.events[event].filter(cb => cb !== callback);
    }
  }
}
```

Publish-subscribe pattern for events.

## Key Points:

- `on` to subscribe.
- `emit` to trigger.
- `off` to unsubscribe.
- Foundation of Node.js events.
