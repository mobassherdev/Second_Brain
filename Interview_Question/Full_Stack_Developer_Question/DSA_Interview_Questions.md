# Big O & Complexity

## Question: What is time complexity?

## Answer:
Time complexity measures how the runtime of an algorithm grows relative to the input size 
. It counts the number of operations an algorithm performs, not actual time in seconds. I focus on the dominant term, ignoring constants and lower-order terms. For example, if an algorithm does 3n² + 5n + 100 operations, I call it O(n²) because the 
² term dominates as 
 grows.

When I analyze time complexity, I look at loops, recursive calls, and operations inside them. Single loops contribute O(n), nested loops O(n²), and recursive algorithms are solved using recurrence relations. This abstraction helps compare algorithms across different hardware and languages.

`python
def find_max(arr):
    max_val = arr[0]
    for num in arr:
        if num > max_val:
            max_val = num
    return max_val

def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n-1):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
`

## Key Points:
- Time complexity measures growth rate, not actual time
- Ignore constants and lower-order terms
- Big O gives the upper bound (worst case)
- Common complexities: O(1), O(log n), O(n), O(n log n), O(n²)
- Focus on the dominant term for analysis

## Interview Tip:
Always clarify whether you are discussing worst-case, average-case, or best-case complexity.

---

## Question: What is space complexity?

## Answer:
Space complexity measures how much memory an algorithm uses relative to the input size. It includes both auxiliary space (extra space used) and input space. I distinguish between in-place algorithms (O(1) extra space) and those requiring additional data structures.

`python
def swap(arr, i, j):
    arr[i], arr[j] = arr[j], arr[i]

def has_duplicates(arr):
    seen = set()
    for num in arr:
        if num in seen:
            return True
        seen.add(num)
    return False
`

## Key Points:
- Measures memory usage relative to input size
- Include both auxiliary space and input space
- O(1) means constant extra space (in-place)
- Recursive algorithms use O(depth) stack space
- Data structures like hash maps use O(n) space

## Interview Tip:
Distinguish between auxiliary space and total space. Optimizing space often comes at the cost of time.

---

## Question: Why is Big O notation important?

## Answer:
Big O notation provides a standardized way to describe algorithm efficiency independent of hardware, programming language, or implementation details. It allows me to compare algorithms theoretically and predict performance at scale. Without Big O, I would have to benchmark every algorithm on every machine.

`python
def get_first(arr):
    return arr[0]

def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
`

## Key Points:
- Provides standardized efficiency comparison
- Independent of hardware and language
- Focuses on growth rate (scaling behavior)
- Helps predict performance for large inputs
- Critical for choosing the right algorithm

## Interview Tip:
Explain that Big O describes the upper bound. Constants matter for small inputs, but Big O matters for scaling.

## Question: What is the difference between O(1), O(log n), O(n), and O(n²)?

## Answer:
O(1) is constant time regardless of input size. O(log n) is logarithmic, halving the problem each step. O(n) is linear, growing proportionally with input. O(n²) is quadratic, growing with the square of input.

`python
def get_middle(arr):
    return arr[len(arr) // 2]

def is_power_of_two(n):
    while n > 1:
        n //= 2
    return n == 1

def count_occurrences(arr, target):
    count = 0
    for num in arr:
        if num == target:
            count += 1
    return count

def has_two_sum(arr, target):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] + arr[j] == target:
                return True
    return False
`

## Key Points:
- O(1): Constant, best possible scaling
- O(log n): Excellent, binary search, balanced trees
- O(n): Linear, acceptable for many problems
- O(n²): Poor for large inputs, nested loops
- O(n³) and higher are generally unacceptable

## Interview Tip:
Know the hierarchy: O(1) > O(log n) > O(n) > O(n log n) > O(n²) > O(2^n).

## Question: How do you calculate the time complexity of an algorithm?

## Answer:
I count operations relative to input size. Single loops contribute O(n), nested loops O(n²). For recursive algorithms, I set up recurrence relations. For loops halving the variable, the complexity is O(log n).

`python
def sum_array(arr):
    total = 0
    for num in arr:
        total += num
    return total

def print_pairs(arr):
    for i in range(len(arr)):
        for j in range(len(arr)):
            print(arr[i], arr[j])

def count_bits(n):
    count = 0
    while n > 0:
        n //= 2
        count += 1
    return count
`

## Key Points:
- Count operations relative to input size
- Ignore constants and lower-order terms
- Analyze loops: single O(n), nested O(n²)
- Recurrence relations for recursive algorithms
- Consider best, average, and worst cases

## Interview Tip:
Walk through the algorithm step by step. Count each operation and identify the dominant term.

## Question: How do you optimize an inefficient algorithm?

## Answer:
I optimize by identifying the bottleneck through complexity analysis, then consider better data structures, eliminate redundant computations, use memoization for repeated subproblems, or apply more efficient algorithms. Profile first, then optimize the hot path.

`python
def has_pair_with_sum(arr, target):
    for i in range(len(arr)):
        for j in range(i+1, len(arr)):
            if arr[i] + arr[j] == target:
                return True
    return False

def has_pair_with_sum_optimized(arr, target):
    seen = set()
    for num in arr:
        if target - num in seen:
            return True
        seen.add(num)
    return False

def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]
`

## Key Points:
- Profile before optimizing (measure first)
- Identify the bottleneck operation
- Consider better data structures
- Eliminate redundant computations
- Use memoization for overlapping subproblems

## Interview Tip:
Explain your optimization process: identify bottleneck, consider alternatives, implement, and verify improvement.

## Question: What is the difference between best case, average case, and worst case complexity?

## Answer:
Best case is the minimum time for any input of size n. Average case is the expected time over all possible inputs. Worst case is the maximum time for any input of size n. Big O typically refers to worst case.

`python
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

def bubble_sort_optimized(arr):
    n = len(arr)
    for i in range(n):
        swapped = False
        for j in range(n-i-1):
            if arr[j] > arr[j+1]:
                arr[j], arr[j+1] = arr[j+1], arr[j]
                swapped = True
        if not swapped:
            break
    return arr
`

## Key Points:
- Best case: minimum operations
- Average case: expected operations
- Worst case: maximum operations
- Big O typically refers to worst case
- Amortized analysis considers sequences

## Interview Tip:
Always specify which case you are analyzing. Worst case provides an upper bound guarantee.

## Question: What is amortized complexity?

## Answer:
Amortized complexity analyzes average performance over a worst-case sequence. Individual operations might be expensive but most are cheap. A dynamic array has amortized O(1) append because the expensive resize happens infrequently.

`python
class DynamicArray:
    def __init__(self):
        self.capacity = 1
        self.size = 0
        self.data = [None] * self.capacity

    def append(self, value):
        if self.size == self.capacity:
            self.capacity *= 2
            new_data = [None] * self.capacity
            for i in range(self.size):
                new_data[i] = self.data[i]
            self.data = new_data
        self.data[self.size] = value
        self.size += 1
`

## Key Points:
- Average performance over a sequence
- Individual operations can be expensive
- Most operations are cheap, expensive ones are rare
- More realistic than worst-case alone
- Common in dynamic arrays, hash tables

## Interview Tip:
Use dynamic arrays as the classic example. Amortized analysis considers sequences, not individual operations.

## Question: Why is binary search O(log n)?

## Answer:
Binary search halves the search space with each comparison. Starting with n elements, after one comparison we have n/2, then n/4, then n/8. The number of times we can halve n before reaching 1 is log₂(n). This requires a sorted array.

`python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
`

## Key Points:
- Halves search space with each comparison
- Logarithmic because we repeatedly divide by 2
- Requires sorted input
- O(log n) much faster than O(n) for large inputs
- Each step eliminates 50% of remaining elements

## Interview Tip:
Walk through an example: 16 elements to 8 to 4 to 2 to 1. That is 4 steps = log₂(16).

# Arrays Fundamentals

## Question: What is an array?

## Answer:
An array is a collection of elements stored in contiguous memory locations, where each element is accessible by its index. Arrays provide O(1) random access because we can calculate the memory address using: address = base + (index x element_size). They are one of the most fundamental data structures.

`python
arr = [10, 20, 30, 40, 50]
first = arr[0]
third = arr[2]
arr[1] = 25
length = len(arr)
`

## Key Points:
- Contiguous memory allocation
- O(1) random access by index
- Fixed size in many languages (static arrays)
- Elements must be same type (in most languages)
- Index starts at 0 in most languages

## Interview Tip:
Mention that arrays are cache-friendly due to contiguous memory. Explain the O(1) access using the base address formula.

---

## Question: What are the advantages of arrays?

## Answer:
Arrays offer O(1) random access, excellent cache performance due to contiguous memory, memory efficiency with no pointer overhead, and efficient iteration. They are the building block for heaps, hash tables, and graphs.

`python
arr = [5, 3, 8, 1, 9, 2, 7]
print(arr[3])
total = sum(arr)
`

## Key Points:
- O(1) random access time
- Cache-friendly (contiguous memory)
- Memory efficient (no pointer overhead)
- Easy to iterate and debug
- Foundation for other data structures

## Interview Tip:
Highlight cache performance. Arrays are used internally by most high-level data structures.

---

## Question: What are the disadvantages of arrays?

## Answer:
Arrays have fixed size (static arrays), expensive insertion/deletion in the middle (O(n) due to shifting), memory waste if underutilized, and no efficient search in unsorted data. Index out of bounds errors are also a concern.

`python
def insert_middle(arr, index, value):
    for i in range(len(arr), index, -1):
        arr[i] = arr[i-1]
    arr[index] = value
`

## Key Points:
- Fixed size (static arrays)
- Expensive insertion/deletion in middle (O(n))
- Memory waste if underutilized
- No efficient search in unsorted data
- Index out of bounds errors possible

## Interview Tip:
Discuss both static and dynamic array limitations. Dynamic arrays mitigate some issues but not all.

---

## Question: What is the difference between static and dynamic arrays?

## Answer:
Static arrays have a fixed size at compile time. Dynamic arrays grow at runtime by allocating new memory and copying elements. Static arrays are on the stack (faster), dynamic arrays on the heap (slower but more flexible). Dynamic arrays have amortized O(1) append due to geometric resizing.

`python
dynamic_arr = []
dynamic_arr.append(1)
dynamic_arr.append(2)
`

## Key Points:
- Static: fixed size, stack allocation, no resize overhead
- Dynamic: grows at runtime, heap allocation, resize cost

## Question: What is the two pointer technique?

## Answer:

# Hashing

## Question: What is hashing?

## Answer:
Hashing maps data of arbitrary size to fixed-size values using a hash function. It provides O(1) average time for insertions, deletions, and lookups. The hash function converts keys into array indices where data is stored. A good hash function distributes keys uniformly to minimize collisions.

`python
class HashTable:
    def __init__(self, size=10):
        self.size = size
        self.table = [[] for _ in range(size)]
    def _hash(self, key):
        return hash(key) % self.size
    def insert(self, key, value):
        idx = self._hash(key)
        for i, (k, v) in enumerate(self.table[idx]):
            if k == key:
                self.table[idx][i] = (key, value)
                return
        self.table[idx].append((key, value))
    def get(self, key):
        idx = self._hash(key)
        for k, v in self.table[idx]:
            if k == key:
                return v
        raise KeyError(key)
`

## Key Points:
- Maps keys to fixed-size values
- O(1) average time for operations
- Hash function determines storage location
- Good distribution minimizes collisions
- Foundation for hash maps, sets, and caches

## Question: How does a hash map work internally?

## Answer:
A hash map stores key-value pairs in an array. The hash function computes an index and the value is stored there. The internal array has a load factor. When it exceeds a threshold (typically 0.75), the hash map resizes (usually doubling) and rehashes all elements to maintain O(1) average performance.

`python

    def __init__(self):
        self.size = 8
        self.count = 0
        self.buckets = [None] * self.size
        self.LOAD_FACTOR = 0.75
    def _hash(self, key):
        return hash(key) % self.size
    def put(self, key, value):
        if self.count / self.size > self.LOAD_FACTOR:
            self._resize()
        idx = self._hash(key)
        if not self.buckets[idx]:
            self.buckets[idx] = []
        for i, (k, v) in enumerate(self.buckets[idx]):
            if k == key:
                self.buckets[idx][i] = (key, value)
                return
        self.buckets[idx].append((key, value))
        self.count += 1
`

## Key Points:
- Hash function computes array index
- Array of buckets (chaining for collisions)
- Load factor triggers resizing
- Resizing rehashes all elements
- O(1) average, O(n) worst case

## Question: How are hash collisions handled?

        bucket = self.table[idx]

                return
        bucket.append((key, value))

## Question: How do you find all permutations of a string?

            return

            if chars[i] not in seen:
                seen.add(chars[i])
                chars[start], chars[i] = chars[i], chars[start]
                backtrack(start + 1)
                chars[start], chars[i] = chars[i], chars[start]

    return result

# Sliding Window Technique

## Question: What is the sliding window technique?

## Answer:
The sliding window technique uses a window (subarray/substring) that slides over data. We maintain start and end pointers, expanding or shrinking based on conditions. This reduces O(n^2) brute force to O(n). Two types: fixed-size and variable-size.

`python
def max_sum_subarray(arr, k):
    window_sum = sum(arr[:k])
    max_sum = window_sum
    for i in range(k, len(arr)):
        window_sum += arr[i] - arr[i - k]
        max_sum = max(max_sum, window_sum)
    return max_sum
`

## Key Points:
- Window defined by start and end pointers
- Fixed-size: constant window size
- Variable-size: dynamic window size
- Reduces O(n^2) to O(n)
- Ideal for contiguous subarray/substring problems

## Question: How do you find the smallest substring containing another string?

## Answer:
Use a sliding window with character frequency maps. Expand to include all required characters, then shrink from the left to find the minimum. O(n) time.

`python
from collections import Counter
def min_window(s, t):
    if not t or not s:
        return ""
    t_count = Counter(t)
    required = len(t_count)
    formed = 0
    window_counts = {}
    ans = float('inf'), 0, 0
    left = 0
    for right in range(len(s)):
        char = s[right]
        window_counts[char] = window_counts.get(char, 0) + 1
        if char in t_count and window_counts[char] == t_count[char]:
            formed += 1
        while left <= right and formed == required:
            if right - left + 1 < ans[0]:
                ans = (right - left + 1, left, right)
            left_char = s[left]
            window_counts[left_char] -= 1
            if left_char in t_count and window_counts[left_char] < t_count[left_char]:
                formed -= 1
            left += 1
    return "" if ans[0] == float('inf') else s[ans[1]:ans[2] + 1]
`

## Key Points:
- Two frequency maps: target and window
- Expand to include all required characters
- Shrink to find minimum valid window
- O(n) time, O(k) space
- Track minimum window throughout

## Question: How does sliding window improve performance?

## Answer:
Sliding window eliminates redundant computations by maintaining a running window state. Instead of recalculating the entire subarray each time (O(nk)), we update incrementally (O(n)).

`python
def max_sum_sliding(arr, k):

    max_sum = window_sum
    for i in range(k, len(arr)):

    return max_sum

## Question: What is bubble sort?

## Answer:
Bubble sort repeatedly steps through the list, compares adjacent elements, and swaps them if in wrong order. Pass through the list until sorted. O(n^2) time, O(1) space. Best case O(n) with early termination.

def bubble_sort(arr):

                arr[j], arr[j+1] = arr[j+1], arr[j]
                swapped = True
        if not swapped:

    return arr

            result.append(left[i])
            i += 1
        else:

            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# Binary Search

## Question: What is binary search?

## Answer:
Binary search is an efficient algorithm for finding an element in a sorted array. It repeatedly divides the search interval in half. If the target is less than the middle, search the left half; otherwise, search the right half. O(log n) time.

`python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
`

## Key Points:
- Requires sorted array
- O(log n) time, O(1) space
- Divide and conquer approach
- Eliminates half the remaining elements each step
- Much faster than linear search for large data

## Question: How do you find the median of two sorted arrays?

                return (max(maxX, maxY) + min(minX, minY)) / 2

        else:

        current = next_node

## Question: How do you convert infix expression to postfix?

## Answer:
Use a stack for operators. Scan infix left to right. If token is operand, add to output. If operator, pop operators with greater or equal precedence from stack and push current operator. Handle parentheses.

`python

    stack = []
    output = []
    for token in expression.split():
        if token.isalnum():
            output.append(token)
        elif token == '(':
            stack.append(token)
        elif token == ')':
            while stack and stack[-1] != '(':
                output.append(stack.pop())
            stack.pop()
        else:
            while stack and stack[-1] != '(' and precedence.get(stack[-1], 0) >= precedence.get(token, 0):
                output.append(stack.pop())
            stack.append(token)
    while stack:
        output.append(stack.pop())
    return ' '.join(output)

- Pop higher precedence operators first
- Handle parentheses
- O(n) time

## Question: How do you implement a queue using an array?

## Answer:

        self.front = (self.front + 1) % self.capacity
        self.size -= 1
        return item

## Question: How do you generate all subsets of an array?

        # Exclude current element

## Question: How do you solve Sudoku using backtracking?

## Answer:
Find an empty cell. Try digits 1-9. Check if the digit is valid (not in row, column, or 3x3 box). If valid, place it and recurse. If no digit works, backtrack.

`python

        for i in range(9):
            if board[row][i] == num or board[i][col] == num:
                return False
        start_row, start_col = 3 * (row // 3), 3 * (col // 3)
        for i in range(3):
            for j in range(3):
                if board[start_row + i][start_col + j] == num:
                    return False
        return True
    
    def backtrack():
        for i in range(9):
            for j in range(9):
                if board[i][j] == '.':
                    for num in '123456789':
                        if is_valid(i, j, num):
                            board[i][j] = num
                            if backtrack():
                                return True
                            board[i][j] = '.'
                    return False
        return True
    
    backtrack()
`

- Constraint satisfaction

## Question: How do you generate combinations?

def lowest_common_ancestor(root, p, q):
    if not root or root == p or root == q:
        return root
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root
    return left if left else right
`

## Key Points:
- Base case: root is null or matches p or q
- Search left and right subtrees
- If both non-null, root is LCA
- If one null, return the other
- O(n) time, O(h) space

## Question: How do you check whether a binary tree is balanced?

# Binary Search Tree (BST)

## Question: What is a Binary Search Tree?

## Answer:
A BST is a binary tree where for every node, all nodes in the left subtree have values less than the node, and all nodes in the right subtree have values greater. This ordering enables O(log n) search, insert, and delete operations.

`python
class TreeNode:
    def __init__(self, val=0):
        self.val = val
        self.left = None
        self.right = None

def search_bst(root, val):
    if not root or root.val == val:
        return root
    if val < root.val:
        return search_bst(root.left, val)
    return search_bst(root.right, val)
`

## Key Points:
- Left subtree: all values less than node
- Right subtree: all values greater than node
- Enables O(log n) operations
- In-order traversal gives sorted order
- Can degenerate to linked list

## Answer:

## Question: How do you delete a node from a BST?

## Answer:

        root = root.left
    return root

## Question: How do you find the kth smallest element in BST?

## Answer:
Perform an in-order traversal and count nodes. When count equals k, return the value. O(k) time, O(h) space. Can also use a Morris traversal for O(1) space.

`python

        while current:
            stack.append(current)
            current = current.left
        current = stack.pop()
        count += 1
        if count == k:
            return current.val
        current = current.right

## Question: What is a max heap?

## Answer:
A max heap is a complete binary tree where every parent node is greater than or equal to its children. The maximum element is always at the root. Used for finding maximum efficiently.

`python
class MaxHeap:
    def __init__(self):
        self.heap = []
    def push(self, val):
        self.heap.append(val)
        self._heapify_up(len(self.heap) - 1)
    def pop(self):
        if len(self.heap) == 0:
            return None
        max_val = self.heap[0]
        self.heap[0] = self.heap[-1]
        self.heap.pop()
        self._heapify_down(0)
        return max_val
    def _heapify_up(self, i):
        while i > 0 and self.heap[i] > self.heap[(i - 1) // 2]:
            self.heap[i], self.heap[(i - 1) // 2] = self.heap[(i - 1) // 2], self.heap[i]
            i = (i - 1) // 2
    def _heapify_down(self, i):
        largest = i
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(self.heap) and self.heap[left] > self.heap[largest]:
            largest = left
        if right < len(self.heap) and self.heap[right] > self.heap[largest]:
            largest = right
        if largest != i:
            self.heap[i], self.heap[largest] = self.heap[largest], self.heap[i]
            self._heapify_down(largest)
`

## Key Points:
- Parent >= children
- Maximum at root
- O(log n) push and pop
- O(1) peek
- Used for max-priority queue

Show the implementation. Explain heapify up and down operations.

## Question: What is heapify?

## Answer:
Heapify is the process of converting a binary tree into a heap. Heapify up: fix violations by moving up (after insert). Heapify down: fix violations by moving down (after extract). Build heap uses bottom-up heapify.

`python
def heapify_up(heap, i):
    while i > 0:
        parent = (i - 1) // 2
        if heap[i] < heap[parent]:
            heap[i], heap[parent] = heap[parent], heap[i]
            i = parent
        else:
            break

def heapify_down(heap, i):
    smallest = i
    left, right = 2 * i + 1, 2 * i + 2
    if left < len(heap) and heap[left] < heap[smallest]:
        smallest = left
    if right < len(heap) and heap[right] < heap[smallest]:
        smallest = right
    if smallest != i:
        heap[i], heap[smallest] = heap[smallest], heap[i]
        heapify_down(heap, smallest)
`

## Key Points:
- Heapify up: after insert
- Heapify down: after extract
- Build heap: bottom-up O(n)
- Fix heap property violations
- O(log n) per operation

## Question: How does heap sort work?

## Answer:
Build a max heap from the array. Repeatedly extract the maximum (swap root with last element, reduce heap size, heapify down). The array becomes sorted in ascending order. O(n log n) time, O(1) space.

`python
def heap_sort(arr):
    n = len(arr)
    # Build max heap
    for i in range(n // 2 - 1, -1, -1):
        heapify_down(arr, n, i)
    # Extract elements
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]
        heapify_down(arr, i, 0)

def heapify_down(arr, n, i):
    largest = i
    left, right = 2 * i + 1, 2 * i + 2
    if left < n and arr[left] > arr[largest]:
        largest = left
    if right < n and arr[right] > arr[largest]:
        largest = right
    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        heapify_down(arr, n, largest)
`

## Key Points:
- Build max heap: O(n)
- Extract max n times: O(n log n)
- Total: O(n log n) time
- O(1) space (in-place)
- Not stable

## Question: How do you find the top K elements using a heap?

    return min_heap

## Question: What is graph traversal?

## Answer:
Graph traversal is visiting all vertices in a graph. The two main approaches are BFS (breadth-first search, level by level) and DFS (depth-first search, going deep first). Both visit all vertices in O(V+E) time.

from collections import deque

`

## Question: How do you perform topological sorting?

## Answer:
Topological sort orders vertices in a directed acyclic graph (DAG) so that for every edge u->v, u comes before v. Use DFS with a stack: push vertices after visiting all neighbors. Or use BFS (Kahn's algorithm).

`python
def topological_sort_dfs(graph):
    visited = set()
    stack = []
    def dfs(vertex):
        visited.add(vertex)
        for neighbor in graph[vertex]:
            if neighbor not in visited:
                dfs(neighbor)
        stack.append(vertex)
    for v in graph:
        if v not in visited:
            dfs(v)
    return stack[::-1]

def topological_sort_bfs(graph):
    in_degree = {v: 0 for v in graph}
    for v in graph:
        for n in graph[v]:
            in_degree[n] += 1
    queue = deque([v for v in in_degree if in_degree[v] == 0])
    result = []
    while queue:
        v = queue.popleft()
        result.append(v)
        for n in graph[v]:
            in_degree[n] -= 1
            if in_degree[n] == 0:
                queue.append(n)
    return result
`

## Key Points:
- Order vertices so edges go forward
- Only works on DAGs (no cycles)
- DFS: push after visiting all neighbors
- BFS: Kahn's algorithm (in-degree)
- O(V+E) time

## Question: What is Dijkstra's algorithm?

## Answer:
Dijkstra's finds the shortest path from a source to all other vertices in a graph with non-negative edge weights. It uses a priority queue (min heap) to greedily select the closest unvisited vertex. O((V+E) log V) time.

`python
import heapq
def dijkstra(graph, start):
    distances = {v: float('inf') for v in graph}
    distances[start] = 0
    pq = [(0, start)]
    visited = set()
    while pq:
        dist, vertex = heapq.heappop(pq)
        if vertex in visited:
            continue
        visited.add(vertex)
        for neighbor, weight in graph[vertex]:
            if distances[vertex] + weight < distances[neighbor]:
                distances[neighbor] = distances[vertex] + weight
                heapq.heappush(pq, (distances[neighbor], neighbor))
    return distances
`

## Key Points:
- Single source shortest path
- Non-negative weights required
- Uses priority queue (min heap)
- Greedy approach
- O((V+E) log V) time

## Question: What is the Bellman-Ford algorithm?

## Answer:
Bellman-Ford finds shortest paths from a single source even with negative edge weights. It relaxes all edges V-1 times. Can detect negative cycles. O(VE) time.

`python
def bellman_ford(vertices, edges, start):
    distances = {v: float('inf') for v in vertices}
    distances[start] = 0
    for _ in range(len(vertices) - 1):
        for u, v, w in edges:
            if distances[u] + w < distances[v]:
                distances[v] = distances[u] + w
    # Check for negative cycle
    for u, v, w in edges:
        if distances[u] + w < distances[v]:
            return None  # Negative cycle exists
    return distances
`

- Detects negative cycles
- O(VE) time
- Slower than Dijkstra
- Relax edges V-1 times

## Question: What is Floyd-Warshall algorithm?

## Answer:
Floyd-Warshall finds shortest paths between all pairs of vertices. It works with negative weights (but not negative cycles). O(V^3) time, O(V^2) space. Simple implementation with three nested loops.

`python
def floyd_warshall(distances):
    n = len(distances)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if distances[i][k] + distances[k][j] < distances[i][j]:
                    distances[i][j] = distances[i][k] + distances[k][j]
    return distances
`

- Works with negative weights
- Not negative cycles
- Simple implementation

## Question: What is Kruskal's algorithm?

## Answer:
Kruskal's finds MST by sorting all edges by weight, then adding them one by one if they don't create a cycle. Uses Union-Find to detect cycles. O(E log E) time.

`python
def kruskal(vertices, edges):
    edges.sort(key=lambda x: x[2])
    parent = {v: v for v in vertices}
    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])
        return parent[x]
    def union(x, y):
        parent[find(x)] = find(y)
    mst = []
    for u, v, w in edges:
        if find(u) != find(v):
            mst.append((u, v, w))
            union(u, v)
    return mst
`

## Key Points:
- Sort edges by weight
- Add edge if no cycle (Union-Find)
- O(E log E) time
- Greedy approach
- Good for sparse graphs

## Question: What is Prim's algorithm?

## Answer:
Prim's grows the MST from a starting vertex. It uses a priority queue to always add the minimum weight edge connecting a visited vertex to an unvisited vertex. O((V+E) log V) time.

`python
import heapq
def prim(graph, start):

        weight, vertex, prev = heapq.heappop(pq)
        if vertex in visited:
            continue
        visited.add(vertex)
        if prev is not None:
            mst.append((prev, vertex, weight))
        for neighbor, w in graph[vertex]:
            if neighbor not in visited:
                heapq.heappush(pq, (w, neighbor, vertex))
    return mst
`

- Grow MST from starting vertex
- Use priority queue for min edge
- O((V+E) log V) time

# Dynamic Programming

## Question: What is dynamic programming?

## Answer:
Dynamic programming solves problems by breaking them into overlapping subproblems, solving each subproblem only once, and storing the results. It works when the problem has optimal substructure and overlapping subproblems. It is essentially recursion with memoization.

`python
# Fibonacci without DP: O(2^n)
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)

# Fibonacci with DP: O(n)
def fib_dp(n):
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
`

## Key Points:
- Overlapping subproblems
- Optimal substructure
- Store results (memoization/tabulation)
- Reduces exponential to polynomial
- Two approaches: top-down and bottom-up

## Question: What is memoization?

## Answer:
Memoization is a top-down DP approach where we store results of function calls and return cached results for repeated inputs. It is recursion + caching. Each subproblem is solved at most once.

`python
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]
`

## Question: What is tabulation?

## Answer:
Tabulation is a bottom-up DP approach where we solve subproblems iteratively, filling a table. We start from the smallest subproblems and build up. No recursion overhead. Often more efficient than memoization.

`python
def fib_tabulation(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
`

## Key Points:
- Bottom-up approach
- Iterative, no recursion
- Fill table from smallest subproblems
- No recursion overhead
- Often more efficient

## Interview Tip:
Compare with memoization. Explain when to use each approach.

## Question: What is the difference between top-down and bottom-up DP?

## Answer:
Top-down (memoization): starts from the main problem, recursively solves subproblems, caches results. Bottom-up (tabulation): starts from smallest subproblems, iteratively builds up to the solution. Both have the same time complexity.

`python
# Top-down (memoization)
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n-1, memo) + fib_memo(n-2, memo)
    return memo[n]

# Bottom-up (tabulation)
def fib_tab(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
`

## Key Points:
- Top-down: recursive + caching
- Bottom-up: iterative + table
- Same time complexity
- Bottom-up avoids recursion overhead
- Choose based on preference

## Interview Tip:
Show both approaches. Explain that they are equivalent in complexity.

## Question: What are common dynamic programming patterns?

`python
# 0/1 Knapsack
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(1, capacity + 1):
            if weights[i-1] <= w:
                dp[i][w] = max(dp[i-1][w], dp[i-1][w-weights[i-1]] + values[i-1])
            else:
                dp[i][w] = dp[i-1][w]
    return dp[n][capacity]
`

## Question: What is a greedy algorithm?

## Answer:
A greedy algorithm makes the locally optimal choice at each step, hoping to find the global optimum. It does not reconsider past choices. Greedy works when the problem has greedy choice property and optimal substructure. It is faster than DP but not always correct.

`python
# Activity selection (greedy)
def activity_selection(activities):
    activities.sort(key=lambda x: x[1])
    result = [activities[0]]
    for i in range(1, len(activities)):
        if activities[i][0] >= result[-1][1]:
            result.append(activities[i])
    return result
`

## Key Points:
- Locally optimal choice at each step
- Does not reconsider past choices
- Faster than DP
- Not always correct
- Needs greedy choice property

## Question: How do you solve activity selection problems?

## Answer:
Sort activities by finish time. Select the first activity. For each subsequent activity, if it starts after the last selected activity finishes, select it. O(n log n) time.

`python
def activity_selection(activities):
    activities.sort(key=lambda x: x[1])
    result = [activities[0]]
    for i in range(1, len(activities)):
        if activities[i][0] >= result[-1][1]:
            result.append(activities[i])
    return result
`

## Key Points:
- Sort by finish time
- Select if starts after last finishes
- O(n log n) time
- Greedy approach
- Maximizes number of activities

## Question: How do you solve interval scheduling problems?

## Answer:
Sort intervals by end time. greedily select intervals that don't overlap with the last selected. This maximizes the number of non-overlapping intervals. O(n log n) time.
